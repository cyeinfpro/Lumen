审查依据：`docs/Image_深度Bug审查报告_2026-09-13.md`。基线提交：`214748bf3f53ac862538974924594a02ecac1994`。目标分支：`main`。

## 修复结论

报告中唯一确认的 P1 问题 `IMG-20260913-01` 已修复。四项条件性风险没有被冒充为已复现或已修复的生产 Bug。原报告内容保持不变，SHA256：`893cf1db0cc663b09e51f9490413a1a7ab7a89992b35e71f698a8297dcaeb9f8`。

空闲会话的 `GET /agent/sessions/{id}/active-run` 合法返回 HTTP 200 / JSON `null`。原解析器在 nullable validator 之前抛出 `response_schema_error`，导致消息与 active-run 的 `Promise.all` 整体失败，消息快照不能应用，轮询被标记为错误。修改前已通过真实生产 API/transport 导入复现，确认 validator 未被调用。

实际修改：

- `response.ts` 增加默认关闭的 `allowNull`；`transport.ts` 与各客户端类型贯通 `allowNullResponse`。只有明确声明 nullable 的接口可以接受 null，损坏 JSON、错误 Content-Type 和非 nullable 接口仍保持严格校验。
- 仅 `getAgentActiveRun()` 显式启用该选项。transport 在调用 fetch 前消费自定义参数；合法 null 不触发重试，validator 仍会执行，也仍可拒绝响应。
- 提取生产恢复函数 `agentSnapshot.ts`，让测试覆盖真实 API → transport → snapshot → store 路径。会话切换和账号 epoch 保护保持不变，旧响应不能污染当前状态。

未修改生产 SSE/轮询协议、海报同步锁实现、数据库、计费或上游请求协议。
