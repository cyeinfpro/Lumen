## Measurement contract

The intended repeated run uses one fresh browser context plus four same-context
reloads per engine/size and ten samples per main operation. A fresh context is
not a cold OS, browser binary, or server filesystem cache. Route interception
disables the HTTP cache, so warm reloads mean the same context and compiled
application, not a production browser-cache benchmark.

Initial readiness means an initial node and edge are attached, followed by two
requestAnimationFrame callbacks. It does not mean all media are decoded or all
graph nodes are simultaneously visible.

Operation time is browser performance.now from before the Playwright action,
through its observable assertion and two animation frames. It includes driver,
actionability and assertion polling overhead. Drag/pan each use eight pointer
steps. Layout includes autosave acknowledgement; it is not pure layout CPU time.
Raw elapsed samples, frame deltas, available Chromium LongTask durations, DOM
node/edge/image counts, request counts and host load are retained in JSON.

DOM counts must be distinguished from model counts. The product virtualizes
offscreen elements. FitView respects minimum zoom (desktop 0.15, mobile 0.08);
it can legitimately leave distant corners outside the viewport. In the first
matrix, desktop 500/1000 fit observations had 414/432 DOM nodes, not 500/1000
simultaneously rendered nodes.

Selection on the mobile context uses a real Playwright touchscreen tap. Drag and
pan use browser mouse input, and zoom uses visible controls or keyboard fallback.
This is mobile viewport/engine coverage, not physical iPhone touch-drag,
pinch-gesture, thermal, or OS lifecycle validation.

The hidden test overrides document.visibilityState and dispatches
visibilitychange, then sends 100 notices over a 5.5-second observation window.
It checks the application's in-browser visibility-event path and request bounds.
It does not establish actual OS background throttling or a real hidden-tab
lifecycle. SSE uses the real subscribers and contiguous event-batch/detail
responses behind a mocked EventSource transport, including duplicate notices and
an explicit snapshot-required gap. It does not benchmark a real network SSE
server.

### Final environment and interpretation

Browser versions and viewports remained Chromium 153.0.8010.12 at 1440×900 and
WebKit 26.5 at 375×812 with reduced motion. Loaded-page telemetry confirmed DPR 1
and the configured inner/visual viewport dimensions in every cell. Earlier
about:blank telemetry is explicitly separate. The host was still the same
10-logical-CPU Apple M1 Max, 32 GiB, Darwin 25.3.0, Node v22.22.0. There was no
CPU-throttling emulation.

The browser-validation window was serialized, but the host was not otherwise
idle. Before/after load was 4.14/5.77/5.83 → 5.05/5.39/5.47.
memory_pressure free was 65% → 63%. fseventsd used roughly 102.4% before and
100.9% after; WindowServer, Python families and other resident services also
used CPU. Command families only, not sensitive arguments, are in the snapshots.
vm_stat swap-ins increased by 127 16-KiB pages (about 1.98 MiB), swap-outs by zero,
and compressor occupancy by 26,434 pages (about 413 MiB). These are measured
interval deltas; historical totals are not presented as current pressure rates.

Observed long frames and the 851 ms maximum available Chromium LongTask warrant
production-build profiling on a controlled host if a responsiveness target is
required. This run does not identify a causal product bottleneck or establish
a frame-rate SLA. WebKit does not expose this LongTask API; “unsupported” does
not mean zero long tasks. Driver steps, actionability, polling and two rAFs are
inside action time; persistence acknowledgement is included for layout.
Fit timing can end before animation/virtualization fully converges, explaining
desktop DOM-count ranges even though model size is fixed.

SSE transport and APIs remain deterministic fixtures, media is repeated local
PNG/one-second MP4, visibility is an in-browser event simulation, and mobile
WebKit is desktop-hosted emulation. Touch selection is real browser input, while
drag/pan are mouse and zoom is control/keyboard. No physical-device multitouch,
pinch, thermal or OS-background lifecycle claim is made. Gesture invalidation
boundaries are additionally covered by the pure touch-state tests.

At completion, port 3127 had no listener and the owned Playwright operation had
exited successfully. The shared heavy-validation window was handed back.
No deployment or publication is performed by this benchmark task.
