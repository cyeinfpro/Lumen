# Image：任务优先的界面重构

日期：2026-09-22。此文记录本轮具体页面决策；全局基础规范仍以 `apps/web/DESIGN.md` 为准。没有更换品牌、复制 macOS 外壳，也没有引入新的组件库。

## 判断顺序

先问用户要完成什么，再决定内容的顺序与尺寸。页面不应要求用户读完产品介绍才找到输入，也不应让没有内容的预览比正在编辑的内容更醒目。卡片用于区分独立对象，分组用间距和分隔线；操作应放在被操作对象附近。

参考 Apple 的 Designing Fluid Interfaces（WWDC18，Session 803）：即时响应、可中断的交互、减少不必要的等待。这里应用的是交互原则，不是用装饰性弹簧或大面积模糊模拟平台外观。

参考资料：https://developer.apple.com/videos/play/wwdc2018/803/

## 1. 创作起点

桌面和移动端复用 `Onboarding`，避免两个平台的起点和文案脱节。

- 首屏只承担两件事：开始输入，或选择可修改的灵感。
- 保留四张本地预览图；小屏两列，宽屏四列。每张只保留画面、类别和方向提示，不重复展示风格标签、画幅徽标、提示词摘要和“一键”营销文案。
- “开始创作”通过现有 composer 展开事件进入输入，不创建会话或提交生成。
- 预设只填写草稿，不自动提交；对话起点在原生 disclosure 内展开，保留键盘操作与可发现入口。
- 删除欢迎组件自己的全屏最小高度与滚动容器，由 Studio shell 统一处理滚动、输入框占位和安全区。
- 整体入场使用共享 `DURATION.normal`（180ms）与 `EASE.develop`，不逐卡延迟。减少动态效果时不设置位移初态或播放过渡。
- 加载时禁用起点操作并保留文字反馈；历史加载错误保留重试，不把错误包装成正常空态。

## 2. 工作流中心

按“继续项目、开始新项目、素材与预设”组织。风格和模特是资源，不与生产流程竞争同等大小的卡片。

- 桌面任务卡片两列，手机一列。卡片标题、简短用途与新建/历史操作优先。
- 输入、输出与步骤放在“流程与准备事项”中按需展开；不再展示未经运行态支持的预计完成时间。
- 删除装饰性编号、重复英文副标题和无帮助的“正式/自由/高级”徽标；保留真正影响预期的“测试”标识。
- 同层级工作流不使用多枚高亮主按钮或 hover 发光。新建操作用中性按钮，历史/资源用可读链接色。
- 最近项目先显示三项，其余可展开，不丢弃已获取记录。
- 完成度、当前阶段、下一步、产出、更新时间与预览均使用 API 原值；未知工作流不产生虚假跳转。
- 小屏操作与 disclosure 至少 44px 高；说明、状态和字段标签不使用禁用态 `--fg-3`。
- 桌面不再预留移动端 tabbar 的底部空白。

## 3. 视频工作台

任务顺序为：生成方式 → 对应素材 → 画面描述 → 参数/费用/提交 → 成片预览。

- 输入区先于预览，并组成单一编辑对象，避免操作散落在多个独立卡片。
- 宽屏参数检查器 300px，在超宽屏为 320px；其余宽度留给内容。检查器在自身滚动区域中靠顶部吸附，不重复计算全局导航高度。
- 手机保留就近的参数入口、费用说明与生成按钮；参数使用现有 BottomSheet，不同时挂载两套参数表单。
- 未生成时，预览只是一段适应亮/暗主题的状态说明；只有真实视频使用深色媒体舞台。成片高度限制为 50dvh / 28rem 中较小者，并使用 object-contain，完整预览仍可打开。
- 比例选项改为紧凑横排形状与标签；选中态同时依靠边框、文字与 `aria-pressed`，不是仅靠发光。
- 移除重复模型名称、重复字段标题；高级种子设置继续按需展开。
- 费用预估、服务可用性、素材约束和提交禁用原因继续使用现有业务模型，不用视觉重构覆盖这些状态。
- 音频控件补充键盘焦点反馈；移动端生成按钮明确使用主操作样式，并关联状态说明。

## 4. 图库工具栏与搜索

浏览素材时，检索、筛选与选择应优先于跳转创作。

- 窄屏操作区允许自然换行，不把按钮藏进没有明显提示的横向滚动区域。
- 工具栏按行组织筛选、状态与操作；创作入口降为次要按钮，避免与当前浏览任务争抢注意力。
- 收起的搜索区域使用 `inert` 和 `aria-hidden`，不再保留隐藏的键盘焦点入口。
- 清空关键词后保留输入焦点；通过键盘关闭搜索后恢复先前的可用焦点。
- Escape 不打断中文输入法组合输入；为直接渲染的清空、关闭、筛选等控件补充可见焦点反馈。
- 搜索框允许收缩，关闭按钮不被压扁；选中状态、按钮文案与辅助说明继续使用语义化主题色。

## 验证要求

使用隔离的 Playwright fixture，不访问真实生成服务，不产生计费请求。测试需覆盖：

1. 320px 手机、375px 手机、平板和桌面；亮色、暗色及 WebKit reduced-motion。
2. 起点只填入草稿、输入焦点可达、无页面横向溢出。
3. 工作流资源分组、展开/收起、真实进度与未知类型处理。
4. 视频输入与预览的 DOM/视觉顺序、空舞台尺寸、参数面板和提交状态。
5. 错误、加载、空态与关闭后的焦点行为。
6. 类型检查、现有单元测试、治理/lint、生产构建和 diff 格式检查。

验证结果以本轮实际执行日志为准；以上为验收标准，不等同于已经通过。
